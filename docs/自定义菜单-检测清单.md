## 二、B 组：必须你来跑（要登微信公众平台后台）

> 🔒 **我进不去微信公众平台后台**（要扫码登录、要管理员身份），所以这一组无法代跑。
> 但从 B1 开始，你每做一步都能立刻用 A 组已验证的工具（干跑 / `curl`）看到结果。

### B1 · 配好本机微信凭证

在 `backend/application-local.yml` 里补上（**这个文件不进 Git**）：

```yaml
wx:
  app-id: 你的AppID
  app-secret: 你的AppSecret
  token: 你之前在公众平台配的Token
```

启动时带上 profile：`SPRING_PROFILES_ACTIVE=local`。

**验收**：重启后端后，`GET /api/menu` 不再返回 T7 那个「配置缺失」的 502。
（此时若无白名单，会变成 502 提示 **40164 / 公网 IP 未加白名单** —— 这是**预期**，去 B2。）

### B2 · 把公网出口 IP 加进白名单 ⚠️

**这是联调路上最容易卡住的一步。**

| 项 | 做法 |
|---|---|
| 为什么要做 | 未认证号调微信接口要求「调用方公网 IP」在公众平台后台登记，否则报 `40164` |
| 怎么查本机公网 IP | `curl ifconfig.me`（或 `curl ipinfo.io/ip`） |
| 加在哪里 | 公众平台后台 → 开发 → 基本配置 → **IP 白名单** |
| ⚠️ 注意 | 你用的是**个人热点**，公网 IP **会变**。每次换网要重新查、重新加 |
| ⚠️ 部署后 | 云服务器的公网 IP 也要加进白名单，否则线上调菜单接口同样 40164 |

**验收**：白名单加好后，`GET /api/menu` 返回 200（微信返回当前线上菜单，未配置时是空菜单结构）。

### B3 · 真发布默认菜单（含中文）

```bash
# 1. 先拿 Cookie 登录
curl -s -c /tmp/wxp-cookie -X POST http://127.0.0.1:18080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"你的密码"}'

# 2. 真发布（dryRun=false）——把默认菜单推到微信
curl -s -b /tmp/wxp-cookie -X POST 'http://127.0.0.1:18080/api/menu?dryRun=false' \
  -H 'Content-Type: application/json' \
  -d '{"button":[
        {"type":"click","name":"关于我","key":"MENU_ABOUT"},
        {"name":"更多","sub_button":[
            {"type":"click","name":"怎么用","key":"MENU_HOWTO"},
            {"type":"click","name":"联系我","key":"MENU_CONTACT"}]},
        {"type":"click","name":"当前进度","key":"MENU_PROGRESS"}]}'
```

**期望**：返回 `{"code":0,"data":{"published":true,"payloadJson":"..."}}`。

**验收（肉眼）**：手机微信里**取消关注再重新关注**该订阅号（或等几分钟），
菜单栏出现 **关于我 / 更多 / 当前进度** 三项，「更多」点开有 **怎么用 / 联系我**。

> 📌 微信菜单变更**不是立刻生效**，客户端有缓存，通常几分钟内刷新；重进公众号会话可加速。

### B4 · 验证「点菜单有回复」（CLICK 事件闭环）

依次点 **关于我 / 怎么用 / 联系我 / 当前进度** 四项。

**期望**：每项都能收到一条文本回复（内容见 `MenuCatalog.clickReplies()`），
且**回复内容与菜单项语义对得上**（这是 `MenuCatalog` 把菜单和文案放一起要防的错位）。

**验收（落库）**：点完之后，管理后台「消息记录」里能查到这几条 `event` 类型的记录。

### B5 · 验证幂等（微信会重推）

微信在没收到回复时会**重试推送**同一条消息，所以 CLICK 事件可能被推多次。

**验收**：连点同一个菜单多次，管理后台里**同一 `MsgId` 只落一条**（消息幂等生效）。
> ⚠️ 注意：事件消息（CLICK）**没有 MsgId**，走的是另一套去重键。
> 这正是 P0 遗留问题之一（事件消息幂等），详见 `docs/P0-遗留问题-改法问答.md`。

## 四、失败排查表（对号入座）

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 启动报 `No qualifying bean of type 'RestClient$Builder'` | 少了 `spring-boot-starter-restclient` | 检查 `backend/build.gradle` 是否有这一行 |
| 编译报 `package com.fasterxml.jackson does not exist` | 导入了 Jackson 2 的包 | 改 `tools.jackson.*`（见方案文档坑 1） |
| `40164 invalid ip` | 公网出口 IP 不在白名单 | 见 B2，用 `curl ifconfig.me` 查了重新加 |
| `40001 invalid credential` | token 被别处作废 | 本地会自动丢缓存重试一次；持续报就查是否多进程在抢 token |
| `40054 invalid button` | 菜单结构不合法 | 本地校验应已拦住；若漏过，把菜单 JSON 贴出来对方案文档 §4.1 |
| `45058` | `view` 菜单指向了非 mp.weixin.qq.com 的域名 | 未认证号不支持，改用 `click` |
| 真发布成功但手机上看不到菜单 | 微信客户端缓存 | 取消关注再关注，或重进会话；等几分钟 |
| 点菜单没回复 | `MenuCatalog` 里没有该 key 的文案 | 核对 key 拼写（全大写 `MENU_*`） |
| 点菜单回复**内容串了** | 菜单定义与文案表不同步 | 两者都在 `MenuCatalog`，应改同一个文件 |
| 前端登录失败 | 账号是 **`admin`**（不是显示名 `云泽`） | 见 admin 鉴权检测清单 |
