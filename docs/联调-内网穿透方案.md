# 联调 · 内网穿透方案（不依赖服务器）

> 状态：**方案已定**（2026-09-22）—— 云泽选定「本机 + 内网穿透」路线
> 目标：**不碰共享服务器、不需要 ICP 备案**，先把 Mac 上的后端暴露到公网，跑通微信真机联调
> 相关：`docs/deploy-部署方案.md`（服务器路线，因资源不足暂缓）｜`backend/scripts/smoke-test.sh`（本地协议自检）

---

## 零、为什么改走这条路

原计划把整套东西（Nginx + 后端 + MySQL）部署到阿里云共享服务器。**预检结果否决了它**：

| 实测项 | 数值 | 判定 |
|---|---|---|
| 内存总量 / 可用 | 1.6 GiB / **仅 457 Mi** | 🔴 紧张 |
| Swap | **0 B** | 🔴 无兜底 |
| 原方案需求（MySQL+后端+Nginx） | 715–820 MB | 🔴 **缺口 260–360 MB** |

按原方案上去，内存吃满 → OOM Killer **随机**杀进程 → 很可能杀掉 `v2fly` / `next-terminal`
（别人的服务）→ 服务器挂机。这正是 `docs/deploy-部署方案.md` §零 红线 **R2** 要拦住的事。

所以本轮改走**最短路径**：后端跑在你 Mac 上，用内网穿透借一个公网域名，先把微信这一关跑通。
服务器路线不废弃，等机器定了（自购 ECS 或你哥那边腾出资源）再迁过去，见 §八。

---

## 一、原理：内网穿透到底解决了什么

你 Mac 现在的处境是：**只有私有 IP（`172.20.10.11`，热点网段），没有公网 IP，路由器上也没开任何入站端口**
—— 微信服务器**无论如何都主动连不到你**。这是 NAT 的天然限制，不是配置问题。

内网穿透的解法是**把建连方向反过来**：让隧道客户端从你 Mac **主动外连**到穿透服务商，双方保持一条长连接。
于是公网上的请求打到服务商的节点，节点顺着这条**已经建好的**连接把数据送进你 Mac。

```
        微信服务器 mp.weixin.qq.com
                 │  ① HTTPS 443（它以为在访问一个正常公网站点）
                 ▼
        ┌──────────────────────────────┐
        │   穿透服务商的公网节点          │  ← 有公网 IP、有 443、域名已备案
        │   https://xxxx.cpolar.cn/wx   │
        └───────────────┬──────────────┘
                        │  ② 顺着「由内向外」建立的长连接送回（NAT 穿透的关键）
                        ▼
        ┌──────────────────────────────┐
        │   你 Mac 上的隧道客户端         │
        └───────────────┬──────────────┘
                        │  ③ 转发到本机回环地址
                        ▼
        ┌──────────────────────────────┐
        │   Spring Boot  127.0.0.1:18080 │
        │   ↓ local profile              │
        │   MySQL  127.0.0.1:3326        │
        └──────────────────────────────┘
```

**关键点**：② 这条连接是你 Mac **主动**发起的（出站），所以**不需要公网 IP、不需要端口映射、不需要动路由器**。
这也是为什么它**不需要 ICP 备案** —— 80/443 与备案问题都由服务商的节点承担了。

## 二、工具选型

| 工具 | 免费版 | 域名形态 | 国内速度 | 缺点 |
|---|---|---|---|---|
| **cpolar** ⭐ | 有（随机域名，含 80/443） | `*.cpolar.cn` 等 | 好（国内节点） | 需注册；免费版**域名每次重启都会变** |
| **cloudflared** | 有（Quick Tunnel 免注册） | `*.trycloudflare.com` | 一般，可能慢/不稳 | 无 SLA，偶发连不上 |
| ngrok | 有（1 个随机域名） | `*.ngrok-free.app` | 差（海外节点） | 国内访问慢 |
| frp | 自建，免费 | 自定 | 取决于你的服务器 | **必须有公网服务器**（当前没有可用的） |

**选 cpolar**（国内节点 + 域名已备案，微信认），**cloudflared** 留作零注册的快速试探。

本项目已把两者都封装进 `deploy/scripts/tunnel.sh`，**自动探测**你装了哪个。

## 三、⚠️ 四个必须提前知道的坑

| # | 坑 | 后果与对策 |
|---|---|---|
| **1** | **免费版域名会变** | 每次重启隧道拿到新 URL → **必须回公众平台后台改「服务器地址」**，否则微信回调 404。这是免费方案的日常成本（付费版可固定域名） |
| **2** | **微信只认 80 / 443** | 隧道必须落在标准端口。cpolar / cloudflared 免费版都给 443，这一条通常不阻塞 |
| **3** | **IP 白名单（`40164`）** | 详见 §四 —— 这是本方案**最麻烦的一环** |
| **4** | **Mac 休眠 = 断线** | 合盖/睡眠后隧道断开，微信回调全部失败。联调期间建议插电源 + 临时关休眠（`caffeinate -dis` 可挡） |

## 四、IP 白名单：分清「哪些要做、哪些不要做」

这里有个**很容易搞混的方向问题**，先说清楚：

> **`40164` 报的是"发起请求的机器"的 IP，与隧道无关。**
> 隧道只影响**别人怎么访问你**（入站）；白名单管的是**你怎么调微信**（出站）。
> 出站请求是从你 **Mac** 直接出去的，所以白名单要填的是**你 Mac 的出口 IP**，不是隧道服务商的 IP。

本机实测出口 IPv4：**`111.183.2.170`**（湖北电信，热点/宽带 NAT）
⚠️ **这个 IP 会变**（重连热点、重启光猫就换）→ 变了就要回后台重加。

**对照表：哪些能力不需要白名单，哪些需要**

| 能力 | 方向 | 需要白名单？ | 说明 |
|---|---|---|---|
| **URL 验证**（后台点「提交」） | 微信 → 你 | ❌ 不需要 | 微信主动来 GET，我们回 `echostr` |
| **文本消息回声** | 微信 → 你 → 微信 | ❌ 不需要 | 被动回复走的是 HTTP 响应体，不是 API 调用 |
| **收到 CLICK 事件并回复** | 微信 → 你 → 微信 | ❌ 不需要 | 同上 |
| **CLICK 事件落库** | 你 → 本地 MySQL | ❌ 不需要 | 不出网 |
| **消息记录 / 数据看板** | 你 → 本地后端 | ❌ 不需要 | 本机访问 |
| **真实下发自定义菜单** | 你 → 微信 API | ✅ **需要** | `cgi-bin/menu/create` |
| **取 access_token** | 你 → 微信 API | ✅ **需要** | `cgi-bin/token` |

**结论**：**微信联调的核心闭环（验证 → 收消息 → 回消息 → 点菜单有回复 → 后台看记录）完全不需要白名单**，
只有「用代码下发菜单」这一件事需要。

**对策（菜单怎么办）**：

1. **首选**：联调时把 `111.183.2.170`（或当时的出口 IP）加进白名单 → `/api/menu` 真发。
   注意 IP 变了要重加。
2. **不想折腾白名单**：先用 **`dryRun` 干跑**验证菜单结构（不调网络、不需要白名单），
   等将来 ECS 部署完（出口 IP 固定）再真发。
3. ⚠️ **不建议**用公众平台后台的图形界面配菜单：那里 click 菜单的 key 由微信自己生成，
   与我们 `MenuCatalog` 的 `MENU_*` 对不上 → **用户点了会「没反应」**（我们按未知 key 静默不回复）。
   这个静默错位很难排查，所以宁可先不配菜单。

### B 组 · 你在 Mac 上执行

```bash
# B1 装隧道工具（推荐 cpolar）
brew install cpolar
cpolar authtoken <你从 cpolar 控制台复制的 authtoken>

# B2 起后端（终端 1，保持前台运行）
cd ~/Desktop/微信公众号/wx-push
WX_TOKEN=你的真实Token ./deploy/scripts/run-local.sh

# B3 起隧道（终端 2）
./deploy/scripts/tunnel.sh
#   → 抄下它打印的 Forwarding 地址，形如 https://xxxxxxxx.r3.cpolar.cn

# B4 本地自检（终端 3）：协议层先过一遍，别急着惊动微信
./backend/scripts/smoke-test.sh 你的真实Token 18080
```

```bash
# B5 防休眠（联调期间建议挂着；Ctrl+C 退出）

```

## 七、排错表

| 现象 | 大概率原因 | 怎么查 |
|---|---|---|
| 后台提交报「参数错误」/ 配置失败 | Token 不一致，或 URL 少了 `/wx`，或隧道没连上 | 看后端日志有无请求进来；`curl` 一下隧道域名 `/wx` |
| 提交成功但发消息没反应 | 隧道断了 / Mac 睡眠了 | 重开隧道；`curl` 隧道域名确认活着 |
| 能收消息但回复「该公众号暂时无法提供服务」 | 后端 5xx（常见：MySQL 没起 / DB 密码不对） | 看后端 stderr；确认 `lsof -iTCP:3326 -sTCP:LISTEN` |
| 域名变了 → 全部失效 | 隧道重启换了随机域名 | 回 C1 改 URL，重新提交 |
| 下发菜单报 `40164` | 出口 IP 不在白名单 / IP 变了 | `curl -4 ifconfig.me` 拿到新 IP，回 C5 加 |
| 下发菜单报 `45058` | 菜单里有 `view` 外链（未认证号不允许） | 本项目菜单全 `click` 型，正常不会遇到 |
| 点了菜单没反应 | 菜单 key 与 `MenuCatalog` 对不上（比如用后台图形界面配的） | 见 §四 第 3 条；改用 `/api/menu` 下发 |
| 隧道域名被微信拒 | 该域名不在微信可信范围 / cloudflared 域名被限 | 换 cpolar；或换隧道工具 |

## 八、与 ECS 部署的关系（迁移路径）

本方案是**过渡方案**，不是终点。两条线并行：

| 线 | 用途 | 何时用 |
|---|---|---|
| **本机 + 内网穿透**（本文档） | 立刻打通微信联调，验证**代码与协议**正确 | 现在 |
| **ECS + Docker Compose**（`docs/deploy-部署方案.md`） | 长期运行，出口 IP 固定、7×24 在线 | 机器定了之后 |

**迁移时不用改代码** —— 隧道只是把请求转发到 `/wx`，换域名/换机器对后端完全透明。
`deploy/` 那套 compose / Dockerfile / nginx.conf 等机器确定后再写（现在写等于猜）。

## 九、明确不做

- ❌ 不在这台共享服务器上跑 MySQL（红线 R2：资源不足，会拖垮别人）
- ❌ 不做 AES 加密模式（未认证号 + 明文模式已定）
- ❌ 不买域名/不备案（本方案不需要）
- ❌ 不用公众平台后台上图形界面配菜单（key 对不上，会造成静默错位，见 §四）
- ❌ 不为了"让它一直在线"去做保活脚本（联调够用即可，长期在线是 ECS 的事）
