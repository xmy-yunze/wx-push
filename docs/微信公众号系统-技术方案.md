### 1.1 自定义菜单的真实能力边界（官方口径）

依据腾讯客服与微信服务市场开发文档：

| 限制 | 说明 |
|---|---|
| 菜单**不能跳转外部网址** | 未认证订阅号只能填公众号内链接：页面模板 / 合集 / 历史消息页面 / 已发表内容 |
| 外链**无绕过办法** | 调 `menu/create` 传外链返回 `45058 invalid url domain`，与是否备案、是否配域名无关 |
| **不支持纯文字**消息类型 | 菜单只能发图文或跳公众号内页 |
| 结构限制 | 一级菜单 ≤ 3 个（≤4 汉字 / 8 字母），二级 ≤ 5 个（≤8 汉字 / 16 字母） |

### 2.1 ⚠️ 待决策：`h5/` 到底做什么

| 反向代理 | Nginx（HTTPS + 443） | 微信要求 80/443 且建议 HTTPS |

### 3.1 报文格式约定（容易踩坑）

| 方向 | 场景 | 格式 |
|---|---|---|
| **微信 → 你**（被动回调） | `POST /wx` 用户消息推送、事件推送 | **XML**（`text/xml`） |
| **你 → 微信**（主动调用） | 创建菜单、获取 access_token | **JSON** |

- Spring MVC 的 `@RequestBody` **默认只认 JSON**，微信发来 `text/xml` 会直接 415 / 解析失败
- 接收侧：读原始 body（`HttpServletRequest` 输入流或 `@RequestBody String`）→ 自行用 XML 解析器转内部对象
- 返回侧：被动回复必须返回 XML **字符串**，`@ResponseBody` 直接返回对象会被序列化成 JSON
- 安全模式下 body 外还裹一层 `<Encrypt>`，需先 AES 解密才能拿到真实报文

## 五、设计模式落点表（本项目核心）

| 模式 | 落点 | 为什么这里合适 |
|---|---|---|
| **模板方法** | 消息处理骨架：校验签名 → 解密 → 解析 → 分发 → 构造回复 | 流程固定，每步可被子类替换 |
| **工厂（简单工厂）** | `MessageHandlerFactory` 按 MsgType 取处理器 | 干掉一长串 if-else |
| **策略** | 文本 / 图片 / 事件各自的处理策略 | 与工厂配合，新增类型不动老代码（开闭原则） |
| **责任链** | 消息前置过滤：日志 → 去重 → 限流 → 权限 | 过滤项可增删、顺序可调 |
| **适配器** | 封装微信各 HTTP 接口，统一调用风格 | 微信接口入参/出参格式不一，隔离变化 |
| **单例 + 双检锁** | `AccessTokenManager` 全局唯一 + 定时刷新 | token 全局共享且存在并发刷新问题 |
| **建造者** | 构造图文消息、菜单树等复杂对象 | 参数多、可选字段多 |
| **组合** | 自定义菜单（一级/二级） | 天然树形结构 |
| **观察者** | 关注 / 取关 / 扫码事件通知业务模块 | 一个事件多方关心 |
| **状态** | 多轮对话（"请输入姓名 → 请输入电话"） | 会话状态流转 |
| **门面** | 对上层暴露统一 `WeChatService` | 隐藏内部复杂度 |
| **装饰器** | 给处理器加日志 / 重试 / 耗时统计 | 横切关注点不侵入业务 |

> **建议**：别一次全上。**先做前 4 个**（模板方法 + 工厂 + 策略 + 责任链）——这是消息主线的自然骨架，其余按迭代引入。一次堆 12 个模式只会让代码变形。

**已落地（截至 2026-09-22）**

| 模式 | 落点 | 状态 |
|---|---|---|
| 模板方法 | `handler/AbstractMessageHandler` | ✅ |
| 工厂 | `dispatcher/MessageHandlerFactory` | ✅ |
| 策略 | `handler/TextMessageHandler`、`EventMessageHandler` | ✅ |
| **适配器** | `gateway/WxApiClient`（封装微信 4 个 HTTP 接口） | ✅ |
| **单例 + 双检锁** | `gateway/AccessTokenManager` | ✅ |
| **建造者** | `domain/menu/MenuBuilder` | ✅ |
| **组合** | `domain/menu/`（`MenuButton` / `SubMenu` / 叶子） | ✅ |
| **门面** | `service/MenuService`、`service/WxMessageService` | ✅ |
| 责任链 | —— | ⬜（去重现由 DB 唯一键保证） |
| 观察者 / 状态 / 装饰器 | —— | ⬜ 未需要 |

> 一次落地 6 种（适配器 + 单例双检锁 + 建造者 + 组合 + 门面 + 策略复用），
> 全部在**自定义菜单**这一块长出来——因为它是唯一需要「主动调微信 + 构造树形结构 + 并发凭证」的功能。
