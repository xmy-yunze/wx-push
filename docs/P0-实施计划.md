| 差异 | 原因 |
|---|---|
| `WxXmlParser` 拆成 **Parser + ReplyXmlBuilder** 两个类 | 一个类既解析又组装违反单一职责，拆开后也更好测 |

## 三、三项任务

### 任务 1 · 签名校验

**思路**：微信发来 `signature`、`timestamp`、`nonce` 三个参数，你自己有一个 `token`（后台填的，不传输）。把 `token`、`timestamp`、`nonce` **三个值按字典序排序**，拼接成一个字符串，做 SHA-1，结果与 `signature` 比对。

**要做到的边界**：
- `GET /wx`：校验通过 → **原样返回 `echostr`**（注意：不能加引号、不能包 JSON）；不通过 → 返回空或 403
- `POST /wx`：校验通过 → 进入消息处理；不通过 → 直接拒绝
- GET 和 POST **共用一个 URL**，用不同的映射注解区分
- SHA-1 用 `MessageDigest`，结果要转成**小写十六进制**
- 比对用**常量时间比较**（`MessageDigest.isEqual`），不要用 `String.equals` 提前返回——这是防时序攻击的细节

> 提示：这一层是安全问题，建议先写一组单元测试（自己构造 timestamp/nonce 算签名），不依赖微信就能验证对不对。

### 任务 2 · 文本消息回声

**微信推给你的报文长这样**（明文模式，`text/xml`）：

```xml
<xml>
  <ToUserName><![CDATA[gh_你的公众号原始ID]]></ToUserName>
  <FromUserName><![CDATA[o用户openid]]></FromUserName>
  <CreateTime>1348831860</CreateTime>
  <MsgType><![CDATA[text]]></MsgType>
  <Content><![CDATA[你好]]></Content>
  <MsgId>1234567890123456</MsgId>
</xml>
```

**你要回给微信的报文**：

```xml
<xml>
  <ToUserName><![CDATA[o用户openid]]></ToUserName>
  <FromUserName><![CDATA[gh_你的公众号原始ID]]></FromUserName>
  <CreateTime>1348831860</CreateTime>
  <MsgType><![CDATA[text]]></MsgType>
  <Content><![CDATA[你说的是：你好]]></Content>
</xml>
```

⚠️ **最容易错的一处**：回复时 `ToUserName` 和 `FromUserName` **必须互换**。收到的 `FromUserName` 是用户，回复时它要变成 `ToUserName`（接收方）。搞反了用户收不到任何东西。

**其他要点**：
- 字段一律用 `<![CDATA[...]]>` 包裹，避免内容里有特殊字符时解析出错
- 回复报文的 `MsgType` 是**回复的消息类型**（`text`），不是请求的类型
- 被动回复的文本内容有长度上限，实现时留个截断保护（具体数值以官方文档为准）
- 返回空字符串 = 不回复

### 任务 3 · 消息落库（原生 MyBatis + XML）

**表结构建议**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK AUTO_INCREMENT | |
| `msg_id` | VARCHAR(64) | 微信消息 ID（**事件消息没有，为 NULL**） |
| `from_user` | VARCHAR(64) | 发送者 openid |
| `to_user` | VARCHAR(64) | 公众号原始 ID |
| `msg_type` | VARCHAR(32) | `text` / `image` / `event` … |
| `event` | VARCHAR(32) | 事件类型（非事件消息为 NULL） |
| `content` | TEXT | 消息内容 |
| `created_at` | DATETIME | 入库时间 |

**关键设计点 —— 幂等**：
- 微信在超时/失败后会**重试推送同一条消息**，所以插入必须幂等
- 做法：给 `msg_id` 加**唯一索引**，用 `INSERT IGNORE`（或捕获重复键异常）
- MySQL 唯一索引允许多个 NULL，所以事件消息（`msg_id` 为空）不会被误挡，这个特性正好可用

**Mapper XML 要点**：
- `<insert>` 上配 `useGeneratedKeys="true" keyProperty="id"`
- 参数用 `#{}`（预编译，防 SQL 注入），**不要用 `${}`
- 接口方法与 XML 的 `id` 必须严格对应，`namespace` 写接口全限定名

## 四、必须避开的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 用 `@RequestBody` 直接映射对象 | 415 / 解析失败（默认只认 JSON） | 读原始 body，自己用 XML 解析器转 |
| `@ResponseBody` 返回对象 | 被序列化成 JSON，微信不认 | 返回 XML **字符串** |
| 回复时收发双方没互换 | 用户收不到任何回复，且**无明显报错** | 严格互换 |
| `echostr` 加了引号或包装 | URL 验证失败 | 原样返回 |
| 主流程里做慢操作 | 超过 5 秒，微信重试 + 用户看到报错 | 去重/限流前置，慢活儿异步化 |
| Token/AppSecret 写死在代码里 | 泄露风险 | 走配置文件 + 环境变量（红线） |

## 五、本地怎么自测（不需要公网）

1. **验签**：自己构造 `timestamp` + `nonce`，按算法算出 `signature`，用 curl 打本地接口，看是否返回 `echostr`
2. **消息处理**：用 curl 直接 POST 一段 XML 到 `/wx`，看返回的 XML 是否正确
3. **联调微信**：本地没有公网 IP，微信访问不到，两个办法——
   - 内网穿透（ngrok / frp / cpolar）临时把本地端口暴露出去
   - 直接部署到云服务器（反正 P0 最后也要部署）

## 六、依赖与配置要点（实际采用）

- 依赖组合**对照 `login-demo`**（同一套 Spring Boot 4.0.7 + MyBatis 4.0.1，已经跑通，省去踩版本兼容的坑）
- **XML 解析不引第三方库**：用 JDK 内置 DOM（`javax.xml`）。报文结构很扁平，DOM 足够；少一个依赖就少一处版本风险
- 微信配置三项（`wx.token` / `wx.app-id` / `wx.app-secret`）走 **环境变量**，不写死在文件里
- `.gitignore` 已排除 `application-local.yml`、`*.key`、`.env`
- ⚠️ **实测环境**：本机 MySQL 经典协议端口是 **3326**（`33060` 是 X Protocol，JDBC 连不上），root 有密码
- ⚠️ **JDK 路径**：Homebrew 装的 JDK 17 不在 macOS 标准位置，Gradle 的 toolchain 检测可能找不到，需要 `export JAVA_HOME=/opt/homebrew/opt/openjdk@17`
